# Виталя

ИИ агент, написанный в рамках проекта для 2-ой Молодёжной научно-технической школы AI:ID

Голосовой (и текстовый) ассистент с распознаванием речи, LLM-«мозгом» с поддержкой вызова инструментов (function calling) и синтезом речи. Виталя умеет не только отвечать на вопросы, но и действовать на компьютере пользователя: открывать приложения, печатать в них текст, работать с файлами в своей песочнице и выполнять shell-команды в изолированном Docker-контейнере.

## Возможности

- **Распознавание речи (ASR)** — [faster-whisper](https://github.com/SYSTRAN/faster-whisper), работает локально на CPU или GPU, модель кешируется на диске.
- **LLM с tool calling** — два переключаемых бэкенда:
  - [Ollama](https://ollama.com/) — локальная модель (по умолчанию `qwen3:14b`), с поддержкой reasoning-трейса;
  - [Gemini API](https://aistudio.google.com/) — облачная модель, с автопроверкой доступности модели и повторными попытками при перегрузке серверов.
- **Синтез речи (TTS)** — [edge-tts](https://github.com/rany2/edge-tts), потоковое воспроизведение через `sounddevice`.
- **Barge-in** — ответ можно прервать голосом/кнопкой прямо во время озвучки.
- **Инструменты агента** — файлы в песочнице, запуск разрешённых приложений, «печать» текста в них (не всегда), выполнение shell-команд.
- **Управление окнами Windows** — поиск окна запущенного процесса (с учётом дочерних процессов), передача фокуса, эмуляция Ctrl+V для ввода текста. Криво, но работает в большинстве случаев (Блокнот на Windows 11 не поддерживается, на 10 работает штатно)
- **Изолированная Docker-песочница** — shell-команды агент выполняет не на компьютере пользователя, а в отдельном контейнере с лимитами по CPU/памяти и сетевой изоляцией; контейнер поднимается лениво и живёт до конца сессии.
- **Whitelist приложений** — агент может открывать только заранее разрешённые программы (системные утилиты — по PATH, сторонние — через реестр Windows App Paths или ручной оверрайд путей).
- **История чатов** — автосохранение диалога на диск, автогенерация заголовка чата через LLM, переключение между сохранёнными чатами.
- **UI** — минималистичный интерфейс на `tkinter`: лог диалога, список чатов, поле для текстового ввода, кнопка «Зажми и говори».

## Архитектура

Ассистент устроен как конечный автомат (`state.py`) с состояниями `BOOT → IDLE → LISTENING → THINKING → ACTING → SPEAKING`, а также `ERROR` и `SHUTDOWN`. Один «ход» диалога (`Assistant.turn`, `engine.py`) выглядит так:

1. Запись голоса или получение текста из UI.
2. Распознавание речи (если был голос).
3. Обращение к LLM с полной историей диалога.
4. Если модель запросила инструмент — выполнение инструмента и возврат результата в LLM (до 3 итераций).
5. Озвучка финального ответа, сохранение хода в историю чата.

Конкретные ASR/LLM/TTS-бэкенды подключаются через `EngineConfig` и не завязаны на остальной код — новый бэкенд достаточно зарегистрировать в соответствующем словаре (`ASR_BACKENDS`, `LLM_BACKENDS`, `TTS_BACKENDS`).

### Структура проекта

```
.
├── main.py            # точка входа, сборка UI + Assistant, сигналы завершения
├── engine.py           # Engines (обёртка над ASR/LLM/TTS) и Assistant (цикл диалога)
├── state.py            # Context, State, конечный автомат состояний
├── config.py            # EngineConfig и вложенные конфиги, чтение/запись config.toml
├── history.py           # сохранение/загрузка/список чатов на диске
├── ui.py                 # окно на tkinter
├── logger.py             # настройка логирования
├── engines/
│   ├── transcriber.py    # ASR-бэкенд (faster-whisper)
│   ├── llm.py             # LLM-бэкенды (Ollama, Gemini)
│   └── tts.py             # TTS-бэкенд (edge-tts)
└── agent/
    ├── tools.py           # инструменты агента + их JSON-схемы для LLM
    ├── apps.py            # whitelist разрешённых приложений
    ├── winctl.py           # управление окнами Windows (поиск, фокус, ввод текста)
    └── docker_env.py       # изолированная Docker-песочница для run_shell
```

## Инструменты агента

Модель может вызывать следующие инструменты (регистрируются декоратором `@tool` в `agent/tools.py`):

| Инструмент | Назначение |
|---|---|
| `list_files` | Показать файлы в рабочей папке пользователя (песочнице) |
| `create_note` | Создать текстовый файл с заметкой |
| `open_app` | Открыть приложение из whitelist (`agent/apps.py`) |
| `type_text` | Напечатать текст в уже открытом приложении (через `winctl.py`) |
| `run_shell` | Выполнить shell-команду в изолированном Docker-контейнере |

Все файловые операции ограничены песочницей (`Context.sandbox`) — выход за её пределы блокируется (`safe_path`).

## Требования

- Python **3.12+**
- Для голосового ввода/вывода — микрофон и колонки/наушники (`sounddevice`)
- Для `open_app` / `type_text` — Windows (используется `pywin32`); для остальной функциональности ОС не принципиальна
- Для `run_shell` — установленный и запущенный [Docker](https://www.docker.com/) (опционально: без него инструмент просто сообщит о недоступности)
- Для `llm_engine = "ollama"` — запущенный локально [Ollama](https://ollama.com/) с нужной моделью
- Для `llm_engine = "gemini"` — ключ [Gemini API](https://aistudio.google.com/apikey)
- Рекомендуется GPU (CUDA) для быстрой работы ASR-модели

## Установка

```bash
git clone https://github.com/Bronitt/Vitalya.git
cd .\Vitalya
pip install -e .
```

(проект использует `pyproject.toml`, поэтому подойдёт и `uv sync` / `poetry install`, если вы используете эти инструменты)

## Настройка

При первом запуске автоматически создаются:

- **`config.toml`** — настройки персонажа, ASR/LLM/TTS-движков и Docker-песочницы. Отсутствующие поля дописываются и валидируются автоматически при каждом запуске.
- **`.env`** — файл для `GEMINI_API_KEY` (нужен только при `llm_engine = "gemini"`; в git не коммитится).

Основные секции `config.toml`:

```toml
[char]
char_name = "Виталя"
char_language = "ru"
char_prompt = "..."          # системный промпт

[asr]
asr_engine = "faster_whisper"
asr_model = "small"          # tiny/base/small/medium/large-v3
asr_device = "cuda"          # cpu/cuda

[llm]
llm_engine = "ollama"        # ollama/gemini
llm_model = "qwen3:14b"
llm_host = "http://localhost:11434"

[tts]
tts_engine = "edge_tts"
tts_voice = "ru-RU-DmitryNeural"

[docker]
docker_enabled = true
docker_image = "python:3.12-slim"
```

Чтобы разрешить агенту открывать сторонние приложения, добавьте их в `THIRD_PARTY_APPS` (`agent/apps.py`) или пропишите путь вручную в `agent/apps_whitelist.json`.

## Запуск

```bash
python main.py
# или с подробным логированием:
python main.py --debug
```

В открывшемся окне зажмите кнопку «Зажми и говори» для голосового ввода или введите текст в поле ввода и нажмите Enter/«Отправить». Закрытие окна корректно завершает работу: досказывается текущий ход, выгружаются модели, останавливается Docker-контейнер (если поднимался).

## Известные ограничения

- `open_app` и `type_text` управляют окнами через `pywin32` — работают только на Windows.
- Без Docker инструмент `run_shell` недоступен, остальной функционал агента при этом не страдает.
- ASR-модель по умолчанию настроена на `cuda` — на машине без GPU нужно переключить `asr_device` на `cpu` в `config.toml`.
